# Quiet growth: native default, native fast, resident-three

The completed profile-off ABCCBA run measures one fixed teacher-forced growth recording. Native fast reduced startup prefill by **20.035%** and turn model time by **1.044%** versus native default. Resident-three reduced decode time by **13.524%**, turn model time by **2.091%**, and all-phase model time by **1.182%** versus native fast. These are separate timing scopes; the decode percentage is not the total runtime improvement. No defaults were promoted.

Two fresh processes per policy used the same frozen helper, eight linked objects, 26 copied shaders and unchanged recorded token IDs. The sequence was A/B/C/C/B/A, so each policy's mean sequence position is 2.5. A is native with selected tile/limit overrides unset (effective 8/256 at 6,136 configured slots, below the frozen 7,680 threshold). B uses native tile64/limit1024. C uses the same fast batching plus replacement routing with gap .30, mass .20, total mass .40, rank48 and maximum three substitutions. C retains the frozen runtime's final-affinity coefficient normalization; this experiment does not use the later native-weight-preservation proposal.

All policies use cache64 GiB, context capacity32768 and prefill chunk512. The nine phases are P1859/P90/D72/P8192/D8/P16384/D8/P38/D8, ending at context26659: 26,563 prefill and 96 decode tokens. No sampling or tool execution occurs. C phase wall times exclude later vector/state export and hashing. Post-phase cache observations and ordinary final footers remain; diagnostic route/IO/timing profiling is disabled. Every recorded DS4 environment is the exact frozen common/policy/shader inventory, after clearing all inherited DS4-prefixed variables.

Startup improvement dominates B's all-phase improvement; its post-startup turn gain is smaller.
