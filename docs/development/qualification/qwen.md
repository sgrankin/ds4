Run from the repository root under the [pressure guard](../../../speed-bench/ideas/pressure_run.py) for model-backed checks. Run `make test-qwen4-kernels test-qwen4-ngrams test-frontends` and `python3 -m unittest discover -s gguf-tools/tests -p test_qwen4_native_ngrams.py`. Build and run the real-model n-gram state test as directed in the usage manual. Failed reads in prefill, decode or MTP must invalidate the frontier, and rebuild and continuation must match an independent session. Table errors must not consume stale staging data.

## Session state, MTP and continuation

Exercise ordinary and MTP, including exact sampling, at short and long initial and continued prefixes, plus snapshot, rewind, checkpoint and logit replay. An older rewind replays retained prefix state; image identity and embeddings are not in the session payload. Same-schedule replay must agree; report different-schedule probability differences separately, since near-tied experts can amplify rounding. After shared loader changes repeat focused DeepSeek and GLM checks. Exercise practical agent editing and real server tool-result continuation with prefix reuse, then follow with an image turn and a text follow-up. Changing back to original BF16 n-grams changes logits, so byte-identical text to the old table is not the quality gate.

## Batch oracle and steering

The native Metal selector admits up to 64 ordinary or 32 speculative members, subject to workspace and compatible checkpoint and steering state. The speculative batch executor has a separate 16-member limit; selector eligibility alone does not promise execution for 32. Matching steering is permitted by the ordinary selector; speculative server eligibility has additional restrictions. Image and other ineligible combinations fall back to ordered execution. The [implementation manual](../../models/qwen38-flash-next/implementation.md) owns the precise eligibility rules. Check isolation and reordered rows at 2, 4 and 8 sessions including sparse prefixes; changed companions must not change the target's full logits. Compare official manifests at batch 1, 4 and 8 using paired losses and API agreement. Different reduction orders need not be bit-identical; investigate greedy mismatches with logit margins without loosening primitive tolerances. Check mixed ordinary/MTP cycles, failed reads and recovery, and the final context slot.

## Server and agent checks

With a four-slot server, test concurrency, tool calls, prefix reuse, cancellation, stop strings and one/two-token limits, with and without MTP. In exact-sampling mode only temperature-zero batched requests may use greedy speculative acceptance; sampled batch requests use ordinary decode. Compare seeded sampled replies in exact mode; default greedy MTP can consume random draws differently. Benchmark prose and code with `speed-bench/session_concurrency_bench`, recording aggregate and per-session throughput, memory and cleanup; run `python3 -m unittest discover -s tests -p test_serve_concurrency_bench.py` to catch truncated/error streams. Use the usage manual's steering and agent tests, including target/control behavior. Run the story test with at least 49K server context, all 16 facts, correction and prefix reuse, and the vision agent tests with independent code assertions.

## Quality references and retained platform work

The [usage manual](../../models/qwen38-flash-next/usage.md) provides both Alibaba manifests and scoring commands. Run default and `--quality`, and long continued-prefill schedules of 1 and 256. Check all counts, finite scores and tokenizer alignment; the hosted model is not a byte-pinned checkpoint and two split-emoji cases lack usable API token alignment. Compare paired case losses and high-confidence disagreements, not just aggregate top-token counts.

The source QA snapshot at `70537d44` (2026-10-28; measurement revision not separately identified) recorded CUDA default-path Q2/Q4 short NLL 0.353129/0.290299 and API matches 4950/5568 and 5127/5568; long NLL 0.155612/0.125160 and 721/766 and 745/766. These are historical references, not native Metal pass thresholds. On M5, single-run Q2/Q4 initial 16K prefill was 1492/1458 t/s, 16K append 1438/1330 t/s and 32K decode 48.7/48.4 t/s. They are indicative, not comparative medians. At 8K and 1024-token chunks the historical plans were 42.86/70.87 GiB excluding disk n-grams; verify physical memory and swap.

The retained CUDA plan ran `make test-qwen4-cuda` and sanitizer checks for dense formats, padded Q2 down rows, Q4_K/MXFP4, recurrent scans, sparse selection and MTP snapshots. Attention groups, dense-only and expert-tile modes additionally covered masked/empty selections, tail groups, odd strides and output guards under memcheck, racecheck and synccheck. Real-model prefill reached 8K on both backends. CUDA session batching was an isolation and ordered-fallback oracle, not evidence of native Qwen throughput. Explicit VRAM admission excluded disk n-grams but included each session workspace. These commands belong to the historical build described in [CUDA qualification](cuda.md), not the current Makefile.
