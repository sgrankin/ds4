# Interaction alignment and constrained generation

On October 27, 2026, the serving interaction path was aligned with the official DeepSeek V4.1 recipe and given native structured decoding. The work preserved client-owned tool execution and normal reasoning. Its small correctness screens passed with recorded exceptions; they do not establish statistical quality equivalence or a general latency improvement.

## Context and decisions

The earlier server already rendered conversations and parsed DSML, but its rendered prompt treated template controls and literal payload alike when tokenizing. Its output parser likewise recognized marker spellings after conversion to bytes. A literal marker could therefore acquire control meaning. The official recipe distinguishes special tokens from ordinary payload; the catch-up preserved that provenance in both directions and kept raw sampled tool-call replay where appropriate. The earlier source audit was evidence of format differences, not measured quality loss.

Tool schemas had historically preceded initial system content to preserve a reusable prefix when system text changed. The ordinary cold checkpoint, however, preferred an exact last-user anchor; its trim applied only to a fallback. Inspection of the installed DeepSeek harness also found that its clock normally arrived as a separate user message, not a changing initial system string. The selected policy followed the recipe's system-then-tools ordering. Ordinary completed history likewise follows the current-tool reasoning rule, while live tool exchanges retain the state they need. The prior custom escaping had protected literal data; it was removed only after token-aware parsing made official raw parameter strings safe.

A shared normalized schema feeds prompting and the grammar compiler. Omitted `strict` means non-strict, explicit true and false are honored, and unsupported guarantees fail clearly. This matters for the inspected DSH client, which did not request strict by default. Required or named tool choice is rejected with thinking enabled rather than silently changing the request; supported non-thinking choices are constrained. JSON, schema and supported regex output use the same compiler, with unsupported combinations rejected. Explicit namespaces map to `namespace::name`; flat names stay flat. Responses tool arguments stream incrementally with stable IDs and exact final accumulation.

DS41 retains temperature 1, top-p 1 and min-p 0.05 defaults, while explicit client overrides win; Flint retains its reference defaults. The user chose min-p as a quantization repair, not on the basis of a new quality comparison. Hosted orchestration, QuickJS and the server's MCP execution path were removed, while client function calls, stateful Responses, caches and native decision APIs remained. Explicit prompt checkpoints select prefix endpoints, not independently reusable chunks.

## Implementation and qualification

The implementation vendored XGrammar 0.2.8 with a native bridge, a bounded compiler cache and a matcher per generation. The recipe supplies declarative constraints; the backend must compile and apply masks, and the client executes returned tools. Known DSML delimiters alone do not demonstrate automatic recipe-to-DeepInfer trigger wiring. Initially constrained generation used a scalar step, retaining the unconstrained fast path. The [interaction report](../../../speed-bench/experiments/interaction-catchup-20261027/README.md) records the settings and qualification.

On DS41 IQ2 and Flint INT4, guarded HTTP checks covered ordinary answers, strict tools, schemas and literal control-marker text. DeepSeek's WebSocket/SDK/restart screen passed 26/26 protocol checks and 12/15 optional quality grades; the frozen `aef775c29745` control reproduced the same three JSON-copy failures. Flint passed 29/29 protocol and 17/17 quality checks. An explicit-cache restart restored a marked 605-token prefix; tests also checked unmarked requests and changed prefixes. These screens establish the exercised behavior, not isolated performance.

The subsequent [packet and MTP report](../../../speed-bench/experiments/constrained-packets-20261027/README.md) compares fixed scalar control `13ecfcd39cd9` with disabled and enabled acceleration. Flint advances masks between sequential GPU steps and overlaps matcher work; its schema case recorded 399 multi-token packets and about 5% lower total time than disabled. DS41 verifies actual drafts using a mask for each prefix, including positive-temperature probability correction and matcher rollback. Its strict-tool case improved about 3.4% while schema worsened about 1.6%; the smaller verification cap showed no clear gain. These limited, partly unseeded observations are not five-sample comparative claims. One Flint baseline returned a valid but wrong enum; it remains a task-quality failure.

A target-only restored checkpoint initially lost the 128-row drafter feature window: a 122-token continuation ran entirely scalar despite a draft flag. A separate fresh-prefill probe proved 22 actual verification cycles, including partial and full acceptance. [Draft-state recovery](2026-10-28-deepinfer-convergence.md) subsequently addressed the restore gap.

## Truncated tool output

A capped control request exposed a separate DSML finalization defect. The October 28 [repair](../../../speed-bench/experiments/dsml-length-20261028/README.md) represents a length- or context-truncated function call as typed incomplete output, retaining argument prefixes, IDs and each call's completion state. Partial calls are excluded from executable tool memory and replay; malformed syntax or unfinished syntax at normal stop remains an error. Responses and Chat retain string prefixes; Anthropic nonstream omits an incomplete object it cannot represent rather than inventing one. Native fixtures and actual streaming and nonstreaming capped requests qualified these distinctions. An incomplete previous-response parent still receives the existing rejection; a safe retry passed.
