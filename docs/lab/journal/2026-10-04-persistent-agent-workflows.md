# Persistent agents: editable history, storage and server reuse

A persistent agent needs facts to remain retrievable after history is shortened. Experiments on October 3–4 combined real file reads, edited context and server checkpoint reuse to test that idea. The measured workflows were small and the latency comparisons generally used short brackets rather than today's five samples per side.

## From edited context to a durable workflow

The October 3 agent screen moved old records to permanent JSON files and read them back with actual tools, keeping the incoming user query fresh. Thirteen workflows and 19 separately graded answers passed. A minimum fresh tail of 128 saved 16.44% and 31.81% whole time on short and long single edits, and 14.71% and 24.65% on repeated edits; the second edit's exact reconstruction was included. Tail 256 saved only 6.55% on the long single edit because checkpoint geometry required 1,514 fresh old tokens rather than 177. These are lookup and arithmetic fixtures, not general generated-agent quality. [Agent report](../../../speed-bench/experiments/agent-suffix-hour6-20261003/README.md).

An actual pair-tape integration first failed because the stdin protocol added a newline that the byte guard did not expect. After correcting that, a 128 MiB selector rejected a forecast exceeding its limit by 2,933,066 bytes. At 160 MiB the selector admitted the edit, but subsequent tool rounds evicted its selected source before the model edited; the third turn fell back to a full 4,245-token prefill. Its external grade passed, but no approximate transaction occurred. These retained failures distinguish an admitted plan from actual reuse. [First failure](../../../speed-bench/experiments/agent-suffix-pair-actual-first-failure-20261003/archive-index.json), [admission failure](../../../speed-bench/experiments/agent-suffix-pair-actual-admission-failure-20261003/README.md), [160 MiB attempt](../../../speed-bench/experiments/agent-suffix-pair-memory160-first-failure-20261003/archive-index.json).

Original-backed pre-RoPE state enabled repeated relocation without accumulating rotation error, while disk checkpoints allowed source reuse after restart. Durable response and conversation records are separate from cache residency: eviction can force recomputation but does not delete conversation items. A response parent appends or forks stored history; it does not replace old history. Full-input edits and explicit conversation item deletion are distinct operations. [Server workflow](../../../speed-bench/experiments/server-workflow-hour12-20261004/README.md), [conversation basics](../../../speed-bench/experiments/conversations-hour13-20261004/README.md), [state cache recipe](../../../recipes/03-state-cache.md).

## Practical quality and retained influence

In the server tail sweep, all nine fixed-context fresh/reuse pairs answered correctly, and all seven actual HTTP workflow steps passed at each setting. Tail 64 saved 22.1% across edited turns and 13.7% including cold sources; tail 128 saved 20.6% across edits. Recurring alignment fallback remained. Core teacher scores and HTTP task times measure different scopes. [Tail curves](../../../speed-bench/experiments/server-suffix-curve-hour14-20261004/README.md).

Retained historical influence could help or hurt: one ordinary shipping case was correct with reuse while fresh shortened context abstained, but a superseded-rule case abstained with reuse while fresh was correct. No usable recall of an entirely omitted rule was shown. Actual archive reads recovered current rules after raising an observed output cap; original calibration and strict-format failures remain in the report. [Retained-history study](../../../speed-bench/experiments/suffix-history-hour15-20261004/README.md).

Four simultaneous histories using two clients and two server slots produced correct edited facts and eight real reads per arm. One suffix arm's warm reply included extra correct prose and failed strict format before any graft. Edited group makespan was 38.64% lower and whole launcher time 17.63% lower in this one workflow pair; cold source groups were 2.13% slower. This is not a general GPU concurrency claim. [Concurrent sessions](../../../speed-bench/experiments/concurrent-sessions-hour19-20261004/README.md).

A repeated Conversations test performed eight real obsolete-item deletions, with fresh reads of codes 57 through 64 and a restart halfway. All 27 turns and 54 replies passed; eight actual SSD/pre-RoPE grafts included seven approximate sources. Whole launcher time fell 58.24% against native brackets. This is one shrinking-history fixture, not proof of unlimited error-free retention. [Eight edits](../../../speed-bench/experiments/repeated-conversations-hour31-20261004/README.md).

## Caller choices and package boundaries

On two coding workflows, stable instructions reduced fresh input from 7,262 to 2,053 tokens through exact prefix reuse and saved 40.49% whole task time against staged-instruction brackets; all first implementations passed 161 checks. This caller-level effect cannot be added to a runtime speedup. A request-scoped WRITE thinking budget of 256 saved 34.8% in the earlier two-task screen, with all 161 code checks passing; a later FINAL budget of 1 saved 24.55% on its own two-task comparison. The role and task are supplied by the caller, not detected automatically. [Stable instructions](../../../speed-bench/experiments/stable-instructions-hour18-20261004/README.md), [WRITE](../../../speed-bench/experiments/server-thinking-hour16-20261004/README.md), [FINAL](../../../speed-bench/experiments/final-thinking-hour20-20261004/README.md).

On two fresh coding contracts, suffix-only and combined resident/suffix settings saved 11.57% and 17.31% of task time against native brackets, with all eight first codes passing 161 checks. Native bracket drift was 1.83%; changed reasoning before graft limits attribution to the package. An installed Pi CLI completed a separate first-write compatibility task through the preset, but did not exercise a context edit or establish latency. [Fresh coding](../../../speed-bench/experiments/fresh-clm-coding-hour32-20261004/README.md), [Pi](../../../speed-bench/experiments/pi-agent-preset-hour34-20261004/README.md).

A 512 MiB SSD quota retained four grafts at 1.23% extra whole time; 128 MiB lost all four sources and added 20.69% whole time. All facts passed, with one separately retained strict-format failure. The preset kept 4,096 MiB headroom; these capacities and hot-cache results describe the tested workflow, not physical SSD traffic. [Quota study](../../../speed-bench/experiments/ssd-budget-hour29-20261004/README.md), [hot cache](../../../speed-bench/experiments/hot-cache-hour21-20261004/README.md), [agent and API recipe](../../../recipes/04-agent-and-api.md).

## Follow-up evidence by question

The individual reports retain the original controls, failed checks, settings and samples for these related questions:

- **Can immutable originals and a shared cache survive repeated use?** Eight pre-RoPE moves and three actual-agent edits passed; a corrected warmed control replaced a mismatched cold comparison. The shared cache passed native reopen/isolation, two interleaved clients across restart and three disk-only grafts after a token-zero selector failure was fixed. [Pre-RoPE](../../../speed-bench/experiments/pre-rope-hour8-20261003/README.md), [shared cache](../../../speed-bench/experiments/state-cache-hour9-20261003/README.md).
- **Does server persistence preserve protocol state?** Initial HTTP reuse passed six answers per cohort, with an odd-shift fallback. Durable responses passed 38/40 initial checks: two copied an earlier marker despite correct facts; all 13 restart checks passed. Conversations passed 45/45 after a query-routing fix, including pending tools, deletion and a visible 409 on concurrent edit. [HTTP](../../../speed-bench/experiments/server-suffix-hour10-20261004/README.md), [responses](../../../speed-bench/experiments/responses-hour11-20261004/README.md), [conversations](../../../speed-bench/experiments/conversations-hour13-20261004/README.md).
- **Do settings generalize to new cases?** The independent client confirmation passed LRU checks, while one native ledger attempt capped before writing and another candidate capped after producing correct code; those capped times are not equal-work speedups. The fresh resident curve found three substitutions fastest of tested points; one versus two was unresolved within drift. WRITE budgets 1/32/128 all passed the two new contracts, without establishing a universal default. [Client confirmation](../../../speed-bench/experiments/server-confirmation-hour17-20261004/README.md), [resident curve](../../../speed-bench/experiments/fresh-resident-curve-hour33-20261004/README.md), [WRITE curve](../../../speed-bench/experiments/fresh-thinking-curve-hour35-20261004/README.md), [SDK smoke](../../../speed-bench/experiments/sdk-preset-hour36-20261004/README.md).
- **Can source geometry improve?** Canonical rendering gained two grafts but lost two when their displacement became odd; newline padding alone gave a smaller result than canonical plus padding. Verified visible-prefix continuation eliminated two regrafts, but remains scoped to matching history and profile. Combined resident routing was compatible yet its 1.42% whole-time difference was smaller than bracket drift. [Canonical](../../../speed-bench/experiments/canonical-suffix-hour23-20261004/README.md), [padding](../../../speed-bench/experiments/parity-suffix-hour24-20261004/README.md), [continuation](../../../speed-bench/experiments/approximate-continuation-hour25-20261004/README.md), [combined routing](../../../speed-bench/experiments/suffix-resident-package-hour26-20261004/README.md).
- **What happens on real coding and repeated deletions?** The suffix coding and combined routing trials passed first-code checks but retained a path-grader failure and a missing-builtin grader failure respectively, later corrected without changing generated code. The separate three-deletion Conversations study passed all 24 logical turns, including restart and fresh reads. [CLM coding](../../../speed-bench/experiments/clm-coding-hour27-20261004/README.md), [combined coding](../../../speed-bench/experiments/clm-resident-package-hour28-20261004/README.md), [three deletions](../../../speed-bench/experiments/repeated-conversations-hour30-20261004/README.md), [resident with reasoning](../../../speed-bench/experiments/resident-combined-hour22-20261004/README.md).

On October 9, stable turn IDs let an actual agent archive and delete an older turn, then retrieve one fact and recall another; the first run exposed a session-date import failure, which was fixed and retested. Opaque random IDs subsequently replaced counters; their file order defines conversation order. The deletion used normal recomputation, so this was not a suffix-speed result. [Stable context](../../../speed-bench/experiments/agent-context-structure-hour42-20261009/README.md), [opaque IDs](../../../speed-bench/experiments/agent-context-opaque-ids-20261009/README.md).
