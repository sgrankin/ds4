# Replay checkpoints and F16 cache tradeoffs

On October 20–21, the project tested bounded decoder replay and compressed KV storage on the verified 1017 IQ2_XXS/Q2_K checkpoint. This is a different model file from the earlier original Flash Q2 studies. The experiments show useful compatibility and memory tradeoffs; their short timing brackets are not five-sample comparisons.

## Bounded replay and persistence

Replay retains full encoder, compressed and index state but approximates selected decoder work during wide prefill. Replay alone was 1.55–2.00% slower; using existing selected-expert batching with 128 replay rows saved 38.17% across three direct 8,192-token fixtures, while 256 rows saved 34.32%. All 12 first answers passed. At 128 rows, shared-teacher mean delta-NLL was +0.00003250 and KL 0.000004469, with no argmax changes. An actual unbatched search/read/answer workflow saved 7.03% against native brackets and included nine fewer search tokens. An initial 105% HTTP regression exposed loss of approximate live state and was retained; a narrow fix allowed verified matching continuation while keeping canonical export and suffix capture blocked. [Replay recipe and evidence](../../../recipes/12-bounded-decoder-replay.md).

The private DRP1 replay envelope and explicit SSD manifest kind preserve approximate identity across restart without making replay a suffix source. An odd 8,193-token state reopened from SSD into F16 with byte-identical state and all 129,280 next-token logits. Two fresh server processes completed actual reads; one ordered cold/restart pair took 47.713 and 18.628 s, with 8,616 tokens restored. This is functional evidence, not a balanced speed comparison. A separate usage fix credited actual restored tokens; its restart reported 8,618 cached tokens matching the hit. [Replay persistence](../../../speed-bench/experiments/replay-persistence-hour50-20261021/README.md), [usage accounting](../../../speed-bench/experiments/state-cache-usage-hour52-20261021/README.md).

## F16 storage and suffix relocation

The main compressed KV values were already BF16-representable. Storing them as F16 halved the main allocation at capacity 262,144 from 1,280.008 to 640.004 MiB; main plus index and raw caches fell from 1,610.010 to 970.006 MiB. Expert cache remained 64 GiB. A same-binary F32/F16 bracket passed 12 first answers and all 22 teacher rows per arm were bit-identical. Direct time differed by less than control drift. The full Metal suite's quantizer tie failed on both baseline and candidate; the existing safe-math diagnostic passed, and the first failure was retained. [Packed KV report](../../../speed-bench/experiments/packed-kv-hour48-20261020/README.md).

At source base `2436f414f083b7b04a9b0dedec4788e6f6bd62d0`, relocation used a 256 KiB F32 repair tile, canonical F32 disk state and immutable BF16 pre-RoPE originals, avoiding a full F32 mirror. F32/F32, F16/F16 and both mixed-layout arms passed; five original-backed full-logit files were byte-identical. The graft itself remained approximate relative to fresh recomputation: mean delta-NLL +0.0000413 and KL 0.0000193 over 16 teacher rows. All seven HTTP steps and six file reads passed, including native and approximate SSD restoration after restart. F16's four-edit sum was 152.864 s versus F32 controls averaging 143.463 s; the ordered matrix was not a serving benchmark. [F16 suffix report](../../../speed-bench/experiments/f16-suffix-hour51-20261021/README.md).

## Does a packed gather help?

Phase analysis attributed about 94% of that edit-time gap to rebuilding prefixes, which also includes expert I/O; it did not identify a rotary-repair regression. A targeted packed gather removed an F16-to-F32-to-F16 round trip before scalar attention. Isolated gather-plus-attention measurements improved by roughly 1–16% across repeated shapes, with exact outputs, but the ordinary full-model bracket's apparent 1.91% saving was within 7.04% control drift. A same-frontier 256-step paired decode measured 20.7582 versus 20.7405 tokens/s, with 273 exact full-vocabulary frontier comparisons: effectively neutral. It is not a whole-model gain claim. [Gather report](../../../speed-bench/experiments/f16-gather-hour53-20261021/README.md).

F16 remains opt-in. The packed reader subsequently became automatic when F16 is selected, with `DS4_METAL_V41_PACKED_F16_GATHER=0` retaining the comparison path. The later decision reflects exact tested outputs and neutral model-level performance, not evidence that all workloads benefit. [F16 recipe](../../../recipes/13-packed-compressed-kv.md).

## Other tested serving and kernel choices

On October 20, keeping IQ2 gate/up reductions in registers through SwiGLU yielded 19.525 versus 19.530 tokens/s in a short fixed-teacher bracket, with no useful gain. Both baseline and candidate failed an SSD-experts retained-RSS check; a begin-only pool trial was reverted and the cause remained unresolved. [Epilogue experiment](../../../recipes/10-q2-kernel-epilogue.md).

Changing mixed-prefill quantum on a two-session fixture exposed an interactive tradeoff: quantum 128 averaged 212.11 s long-request wall and a 7.32 s worst stream gap; quantum 2048 took 96.02 s but its worst gap rose to 20.39 s. Quantum 512 took 304.50 s and a 19.30 s gap. The first bracket was interrupted by unrelated updates and the entire clean bracket restarted; the result is one workload, not a general throughput claim. [Scheduler comparison](../../../recipes/08-official-inference-lessons.md).

Incremental tool schema announcements initially saved 46.30% on a favorable durable-parent workflow but regressed 8.17% on the ordinary live case. Removing duplicate schema copies later saved 57.45% on the durable-parent workflow while the short live workflow remained 4.00% slower; all eight first workflows and real reads passed. Single-copy rendering became the then-default with a legacy override. [Tool-schema recipe and results](../../../recipes/11-incremental-tool-schemas.md).
