# Native Zig rewrite and serving boundaries

The October 2026 rewrite made Zig the owner of the ordinary DeepSeek runtime and its frontends, while retaining the real Objective-C Metal boundary and existing shader and library dependencies. This was an ownership and readability change, not a claim that translating C automatically improves inference speed. The [qualification report](../../../speed-bench/experiments/zig-qualified-20261022/README.md) records the completed scope and evidence.

## Why rewrite in stages

A mechanical translation preserved the shape of the C program without delivering the intended readable interfaces and ownership. It was archived as `zig-mechanical-archive`; the handwritten effort started again from C on `zig-modular`. The aim was idiomatic, comprehensible components with meaningful original comments and explicit lifetimes, not a translated facade or a line-count target. Small C routines could remain more direct, and Objective-C continued to own Metal objects and ARC operations.

The selective migration used bounded one-hour slices, each replacing an actual owner and testing through existing production-linked boundaries. It started with checkpoint and KV persistence, GGUF cursor and metadata reads, and host utilities; later slices covered tokenization, numerical sampling, image processing, prompt rendering, Metal controllers, CLI and benchmark frontends. Shared records were not duplicated across C and Zig. Tests compared bytes, state and real callers across the language boundary rather than merely exercising a new wrapper. The [selective migration report](../../../speed-bench/experiments/zig-final-20261022/README.md) and [combined qualification](../../../speed-bench/experiments/zig-combined-20261022/README.md) link the individual slices and retained tradeoffs.

The selective stage passed 78 CPU fixture invocations, four builds and 90 Debug router GPU cases. Its real persistent-agent comparison completed twelve turns, six fresh archive reads and six SSD/pre-RoPE grafts; pressure stayed normal. Its build tradeoff was mixed: full builds were 9.184 s for Make versus 9.557 s native, while a migrated Metal-controller edit averaged 3.2460 versus 0.5005 s. The sampling fixture's CPU improvement was not a whole-model throughput result, and the resident-route task ran 1.60% longer than its C bracket mean. The [final selective report](../../../speed-bench/experiments/zig-final-20261022/README.md) records individual results and stopped measurements.

The later handwritten engine and session work moved model execution, memory, frontiers and lifecycle into native owners. The resulting DeepSeek V4.1 Flash Metal scope included the engine, session/cache controllers, Agent, server, CLI, benchmark, Eval and Web helper. MSL, actual Metal objects and pipeline catalogs, third-party dependencies and C transport stayed explicit boundaries; other model families and legacy paths still had C owners at that checkpoint. The detailed branch history was retained as `zig-rewrite-history-20261022`; the qualified branch was condensed for review. At the final combined checkpoint, 98 host/CPU, 45 GPU and six diagnostic invocations passed, together with exact ordinary frontiers, trained speculative cycles, six-turn agent tasks, vision cases and durable C-to-native server restart. Full rebuilds cost 29.5% more while one F32 controller edit cost 67.1% less; these short build screens are not a blanket build-speed conclusion. Two-host tensor parallelism and actual browser/consent behavior were not qualified. A packed-gather launch-width bug and a Debug interactive stack exhaustion were found and fixed during integration; the initial failed runs remain in the reports. See the [final qualification](../../../speed-bench/experiments/zig-qualified-20261022/README.md) and the [module guide's grouped evidence index](../../../src/README.md#qualification-and-evidence) for engine, state, agent, server and Metal component reports. The [engine checkpoint](../../../speed-bench/experiments/zig-engine-final-20261022/README.md) was an intermediate result, not completion of the whole rewrite.

## Serving and adoption

On October 23, logical request records and model preparation moved behind a model adapter: the adapter owns model aliases, reasoning policy and rendering, while the server owns durable history. Cross-version and native-only HTTP campaigns exercised concurrent sessions, cancellation, streaming and restart; no numerical kernel or checkpoint format changed. The [serving boundary report](../../../speed-bench/experiments/zig-serving-boundary-20261023/README.md) records the checks.

Stateful Responses WebSocket serving followed, with sequential requests per socket and concurrency across sockets. The ReleaseFast and Debug integrations each passed 26 required checks, including a real external function tool and restart. Ten official cases passed serially with longer timeouts; the original parallel runner passed only 3/10 when it overloaded the two-slot server, so that result does not establish a schema failure. Three of 15 answer probes remained wrong in the independent C control as well. Stable instructions and tools reused 292 of 317 prompt tokens in one file lookup loop, evidence of prefix reuse rather than a whole-agent speedup. The [WebSocket report](../../../speed-bench/experiments/responses-websocket-20261023/README.md) owns these measurements and qualification details.

Adoption then made all five production mains Zig and removed duplicate frontend owners. Frozen-parent DeepSeek, GLM and Qwen short continuations and reported top logits matched; host, GPU and WebSocket checks passed. An inherited DeepSeek FP4 midpoint fixture failure reproduced in the control, and a resident GLM attempt was pressure-stopped before the working SSD path was used. See the [adoption report](../../../speed-bench/experiments/zig-adoption-20261023/README.md). This history is a qualification at the recorded revisions, not a guarantee for every later change.

A separate read-only October 28 observation identified an unselected future experiment: the batched coordinator uses an ordinary idle prefill quantum of 2048 independently of `--prefill-chunk`; `--mixed-prefill-quantum` applies to active-generation overlap. A controlled 2048 versus 8192 comparison would need to retain batching and check actual forward segments, expert reads, whole-edit time and waiting decode/cancellation latency. It was not authorized or launched by that observation.

## Upstream catch-up and selected reads

On October 23 the rewrite caught up with upstream through an adaptation merge: first parent `9944e786f715` was the native tip and second parent `ee7e8405232c` recorded the reviewed upstream boundary. The tree retained the native implementation with deliberate ports, rather than treating automatic conflict resolution as a C-to-Zig translation. Significant omissions and deferrals must be recorded because the second parent marks those upstream changes as considered. The CUDA-only implementation was not ported to Metal.

One port added verified, resumable DS4.1 Flash 1017 MXFP4 downloads and upstream GGUF shard assembly; standard shards need tensor-directory reconstruction and 16 KiB alignment, not raw concatenation. Offline fixtures qualified the downloader, not the large checkpoint: its approximately 467 GiB output and 935 GiB shard/output reserve exceeded the available space at that time.

A separate Metal experiment sorted selected-prefill reads by file offset, without changing routing or decode. The larger-cache arm was pressure-stopped. Two smaller ABBA screens favored sorting by 2.13% and 1.72%, but candidate times also matched individual controls closely and a control varied by 2.89%; all compared 129280-logit frontier rows matched exactly. The performance result was inconclusive, the temporary knob was removed, and the larger-cache case remained unqualified. This does not reject CUDA's combined sorting and coalescing policy. The [selected-read report](../../../speed-bench/experiments/upstream-selected-read-20261023/README.md) retains settings, failures and the reproduction patch.
