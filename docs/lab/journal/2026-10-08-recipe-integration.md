# Integrating resident routing with editable context

The October 8 follow-up tested whether the previously measured pieces worked together on actual coding workflows. A combined opt-in package met the then-current 20% whole-task target on two unused tasks, but individual timings used short native brackets and do not satisfy the later five-sample methodology.

## Setup and findings

The comparison used the original Flash Q2 model and recipe baseline `0316b956f8236d810f50c2ae0a6fda9f77ce35d6`, with one guarded model job at a time. Warm-prefill routing froze residency at the start of a prefill call. Three substitutions saved 10.64% warm-append time and 5.98% coding-task time against native means; all eight first codes passed 161 checks, and paired mean delta-NLL was +0.005043 nats/token. One substitution reduced drift without establishing latency savings. The 20% target was unmet, so the new prefill setting remained opt-in. [Prefill report and curve](../../../speed-bench/experiments/recipe-prefill-hour37-20261008/README.md).

Faithful discussion compaction in a READ/edit/WRITE/FINAL server workflow saved 11.66–12.38% whole-task time; all ten first writes passed 161 checks. Six standalone quality screens covered ordinary, favorable, equivalent-instruction and stale-rule cases, with mean delta-NLL from −0.01434 to +0.01781. One fresh answer's Markdown fence failed the raw format check, though its extracted function passed. The requested 64/128/256 tails had equal actual fresh coverage in the server workflow, so their fastest setting was not a general optimum. [Compaction report](../../../speed-bench/experiments/recipe-compaction-hour38-20261008/README.md).

Insertion and growing replacement required right shifts. The extension uses immutable pre-RoPE originals for even shifts and leaves the latest user query fresh. Three repeated moves, right 66, left 128 and right 514, preserved the original checkpoint and masters; a missing-original right move rejected without session mutation. Six first writes passed 161 checks, with 19.46% lower whole-task time against native means. Four coding screens had mean delta-NLL between −0.00393 and +0.00229, but five raw Markdown-fenced outputs failed format even though extracted functions passed. The right-shift flag was default-off at this stage. [Right-shift report](../../../speed-bench/experiments/recipe-rightshift-hour39-20261008/README.md).

## Combined result

On unused interval-grouping and dependency-layer tasks, combined warm-prefill and decoder resident routing plus suffix reuse took 196.35 s versus native brackets of 263.22 and 250.25 s, a 23.52% saving against their mean. Suffix reuse alone took 223.76 s. All ten first writes passed their 161-case graders without retries or caps; a combined repeat took 196.43 s and matched code and usage. Native drift was −4.93%, so the faster control is also reported in the source. The server `persistent-fast` preset exposed the measured package as an opt-in, retaining explicit overrides and caller-selected thinking. [Combined report and plot](../../../speed-bench/experiments/combined-fresh-hour40-20261008/README.md).

A subsequent direct agent integration on October 9 passed ten fresh-file answers in five CLI runs; actual compaction reused 696 tokens, while an odd-shift fallback remained. The favorable aligned fixture's approximately 46.5% saving is a small historical workflow observation, not a general speed guarantee. [Agent integration](../../../speed-bench/experiments/agent-package-hour41-20261009/README.md), [suffix recipe](../../../recipes/02-suffix-reuse.md).
